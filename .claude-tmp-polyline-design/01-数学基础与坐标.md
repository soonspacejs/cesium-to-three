## 2. 新增：`ArcType`（`line/line-options.ts` 内或 `math/arc-type.ts`）

对齐 Cesium `Core/ArcType.js`：

```typescript
/** 折线在椭球面上的连线方式。 */
export const ArcType = {
  /** 直连（ECEF 弦，不沿曲面）。仅当线段极短或调用方明确要求时用。 */
  NONE: 0,
  /** 大地线（最短路径，Vincenty）。默认。 */
  GEODESIC: 1,
  /** 恒向线（罗盘恒定方位角）。航海/航空图常用。 */
  RHUMB: 2,
} as const;
export type ArcType = typeof ArcType[keyof typeof ArcType];
```

公开选项里以字符串暴露：`'none' | 'geodesic' | 'rhumb'`，构造期映射到上述枚举（doc 09）。

> **为何必须支持三种、且 geodesic 为默认**：贴地线的视觉正确性取决于「相邻折点之间走哪条曲面路径」。直接 ECEF 弦在长段（>几十 km）会穿入椭球内部、加密点投回地表后与真实大地线偏离，山区尤其明显。Cesium 默认 GEODESIC。本设计不以「弦中点投影」替代真大地线（那是 polygon wall 的做法，对面填充够用，对线的轨迹不够精确）。

## 3. 新增：`EllipsoidGeodesic`（`math/ellipsoid-geodesic.ts`）

移植自 `Core/EllipsoidGeodesic.js`（523 行）。职责：给定起止 `Cartographic`，求两点间**大地线**的 surfaceDistance、起止航向，并支持按弧长插值取中间点。贴地线加密（doc 02）逐段构造一个 `EllipsoidGeodesic`，按 `granularity` 取等距中间点。

### 3.1 类结构

```typescript
export class EllipsoidGeodesic {
  private _ellipsoid: { maximumRadius: number; minimumRadius: number };
  private _start: Cartographic;     // height 置 0

  private _startHeading?: number;

              ellipsoid = { maximumRadius: WGS84_X_RADIUS, minimumRadius: WGS84_Z_RADIUS });
```

### 3.2 Vincenty 逆解（`vincentyInverseFormula`）——求距离与航向

输入 `major=a, minor=b, lon1,lat1, lon2,lat2`。完整算法（逐字）：

```
f  = (a - b) / a
L  = lon2 - lon1
U1 = atan((1 - f) * tan(lat1))
U2 = atan((1 - f) * tan(lat2))
cU1=cos U1; sU1=sin U1; cU2=cos U2; sU2=sin U2
cc=cU1*cU2; cs=cU1*sU2; ss=sU1*sU2; sc=sU1*cU2
λ = L;  λDot = 2π
do {
  cosλ=cos λ; sinλ=sin λ
  temp = cs - sc*cosλ
  sinσ = sqrt( cU2²·sinλ² + temp² )
  cosσ = ss + cc·cosλ
  σ = atan2(sinσ, cosσ)
  if (sinσ == 0) { sinα=0; cos²α=1 }
  else { sinα = cc·sinλ / sinσ; cos²α = 1 - sinα² }
  λDot = λ
  cos2σm = cosσ - 2·ss / cos²α       // 不是有限值则置 0
  λ = L + computeDeltaLambda(f, sinα, cos²α, σ, sinσ, cosσ, cos2σm)
} while (|λ - λDot| > 1e-12)          // EPSILON12

u² = cos²α · (a² - b²) / b²
A  = 1 + u²·(4096 + u²·(u²·(320 - 175·u²) - 768)) / 16384
B  = (u²·(256 + u²·(u²·(74 - 47·u²) - 128))) / 1024
cos²2σm = cos2σm²
Δσ = B·sinσ·( cos2σm + (B·( cosσ·(2·cos²2σm - 1)
        - (B·cos2σm·(4·sinσ² - 3)·(4·cos²2σm - 3))/6 ))/4 )
distance    = b · A · (σ - Δσ)
startHeading= atan2( cU2·sinλ , cs - sc·cosλ )
endHeading  = atan2( cU1·sinλ , cs·cosλ - sc )
// 写回 _distance / _startHeading / _endHeading / _uSquared
```

辅助：

```
computeC(f, cos²α) = f·cos²α·(4 + f·(4 - 3·cos²α)) / 16
computeDeltaLambda(f, sinα, cos²α, σ, sinσ, cosσ, cos2σm):
  C = computeC(f, cos²α)
  return (1 - C)·f·sinα·( σ + C·sinσ·( cos2σm + C·cosσ·(2·cos2σm² - 1) ) )
```

> **退化保护**：当两点近乎对跖（`|angleBetween| ≈ π`）时 Vincenty 不收敛。Cesium debug 断言 `|abs(angleBetween)−π| ≥ 0.0125`。移植时改为：若 `L==0 && lat1==lat2` 直接 `distance=0`；对跖情形在 doc 02 由「本初子午线 + IDL 拆段」预先切碎，使任何单段都远离对跖，故实践中不触发。

### 3.3 `setConstants` ——预算插值系数（一次）

逆解后调用，预算 `a0..a3`、`u2Over4/u4Over16/u6Over64/u8Over256`、`cosineHeading/sineHeading/tanU/cosineU/sineU/sigma/sineAlpha/cosineAlpha/distanceRatio` 等常量存入 `_constants`。完整公式（逐字）：

```
a=maxR; b=minR; f=(a-b)/a
cosH=cos(startHeading); sinH=sin(startHeading)
tanU = (1-f)·tan(start.latitude)
cosU = 1/sqrt(1 + tanU²);  sinU = cosU·tanU
sigma= atan2(tanU, cosH)
sinα = cosU·sinH;  sin²α = sinα²;  cos²α = 1 - sin²α;  cosα = sqrt(cos²α)
u2Over4=u²/4; u4Over16=u2Over4²; u6Over64=u4Over16·u2Over4; u8Over256=u4Over16²
a0 = 1 + u2Over4 - 3·u4Over16/4 + 5·u6Over64/4 - 175·u8Over256/64
a1 = 1 - u2Over4 + 15·u4Over16/8 - 35·u6Over64/8
a2 = 1 - 3·u2Over4 + 35·u4Over16/4
a3 = 1 - 5·u2Over4
distanceRatio = a0·sigma - a1·sin(2σ)·u2Over4/2 - a2·sin(4σ)·u4Over16/16
              - a3·sin(6σ)·u6Over64/48 - sin(8σ)·5·u8Over256/512
```

### 3.4 `interpolateUsingSurfaceDistance(distance, result)` ——按弧长取点

完整公式（逐字，C = `_constants`）：

```
s = C.distanceRatio + distance / C.b
（cos2S..sine8S = cos/sin(2s,4s,6s,8s)；s2=s²; s3=s·s²）
sigma =
   2·s3·u8Over256·cos2S / 3
 + s·( 1 - u2Over4 + 7·u4Over16/4 - 15·u6Over64/4 + 579·u8Over256/64
       - (u4Over16 - 15·u6Over64/4 + 187·u8Over256/16)·cos2S
       - (5·u6Over64/4 - 115·u8Over256/16)·cos4S
       - 29·u8Over256·cos6S/16 )
 + (u2Over4/2 - u4Over16 + 71·u6Over64/32 - 85·u8Over256/16)·sine2S
 + (5·u4Over16/16 - 5·u6Over64/4 + 383·u8Over256/96)·sine4S
 - s2·( (u6Over64 - 11·u8Over256/2)·sine2S + 5·u8Over256·sine4S/2 )
 + (29·u6Over64/96 - 29·u8Over256/16)·sine6S
 + 539·u8Over256·sine8S/1536
theta    = asin( sin(sigma)·C.cosineAlpha )
latitude = atan( (C.a / C.b)·tan(theta) )
sigma    = sigma - C.sigma
cos2σm   = cos( 2·C.sigma + sigma )
sinσ=sin(sigma); cosσ=cos(sigma)
cc = C.cosineU·cosσ;  ss = C.sineU·sinσ
λ  = atan2( sinσ·C.sineHeading , cc - ss·C.cosineHeading )
l  = λ - computeDeltaLambda(C.f, C.sineAlpha, C.cosineSquaredAlpha,
                            sigma, sinσ, cosσ, cos2σm)
result.longitude = _start.longitude + l
result.latitude  = latitude
result.height    = 0
```

> 数据类型：移植类全程用 JS `number`（Float64），不上 GPU；只在最后 `cartographicToCartesian` 转 ECEF 时进入几何数组（doc 02）。所有三角函数用 `Math.*`，常量保留全精度。

## 4. 新增：`EllipsoidRhumbLine`（`math/ellipsoid-rhumb-line.ts`）

移植自 `Core/EllipsoidRhumbLine.js`（751 行）。职责：恒向线版本，接口与 `EllipsoidGeodesic` 对称：

```typescript
export class EllipsoidRhumbLine {
  constructor(start?: Cartographic, end?: Cartographic, ellipsoid?);
  get surfaceDistance(): number;
  get heading(): number;
  setEndPoints(start: Cartographic, end: Cartographic): void;
  interpolateUsingSurfaceDistance(distance: number, result: Cartographic): Cartographic;
  /** doc 02 拆段时用：求恒向线与某经线的交点。 */
  findIntersectionWithLongitude(intersectionLongitude: number, result: Cartographic): Cartographic;
}
```

要点（恒向线基于等角投影 / Meridian arc，移植时逐函数对照源码 `Core/EllipsoidRhumbLine.js`）：
- `_calculateHeading`：用 isometric latitude 差与经差求恒定方位角。
- `_calculateArcLength`：子午线弧长积分（用椭球级数展开常量 `_ellipticalArcLength*` 系列）。
- `interpolateUsingSurfaceDistance`：沿恒向线推进固定弧长，反算 lon/lat。
- `findIntersectionWithLongitude`：doc 02 跨本初子午线/IDL 拆段在 RHUMB 模式下定位交点。

> RHUMB 移植量较大但纯数学、无 GPU/Three 依赖，可独立单测（与 Cesium 同输入对拍）。**若项目当前业务只用直线/大地线，RHUMB 可作为第二阶段交付，但 `line-densify.ts` 的 arc 分发结构必须从一开始就预留三分支（见 doc 02），不得写死 geodesic。** 这不是简化——是接口完整、实现按 arcType 分发，RHUMB 分支在其类就绪前抛 `GeoForgeError('ARC_TYPE_UNAVAILABLE', 'RHUMB')` 而非静默回退到 geodesic。

## 5. `getPosition` / `direction`（几何内联小工具，doc 02-04 共用）

对齐 Cesium：

```typescript
/** cartographic（指定 height）→ ECEF。复用 cartographicToCartesian。 */
function getPosition(carto: Cartographic, height: number, out: Vector3): Vector3 {
  const c = createCartographic(carto.longitude, carto.latitude, height);
  return cartographicToCartesian(c, out);
}
/** out = normalize(target - origin) */
function direction(target: Vector3, origin: Vector3, out: Vector3): Vector3 {
  out.subVectors(target, origin).normalize();
  return out;
}
```

> 注意：贴地线几何全程用 **Three.js `Vector3` 承载 ECEF（Float64 语义）**。Three 的 `Vector3` 内部是 Float64（JS number），与 Cesium `Cartesian3` 等价；只有最终装配 `position3DHigh/Low` 时才落到 Float32（经 RTE 拆分），与 polygon 路径完全一致。
